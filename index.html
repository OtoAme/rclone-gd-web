Local Drive Sync

个人在自己的电脑上，用开源程序 rclone 访问自己的 Google 云端硬盘时，所使用的 OAuth 客户端。

这个应用是什么

Local Drive Sync 是 Google Cloud 项目里登记的 OAuth 客户端名称。用户在自己的电脑上运行 rclone，并在 rclone config 里填入这个客户端之后，rclone 才能代表用户调用 Google 云端硬盘 API。

这样做的原因写在 rclone 的文档里：rclone 项目共用的 client_id 正在停用，使用者需要创建自己的客户端。本客户端只服务创建它的开发者本人，在其自己控制的电脑上，访问其有权使用的 Google 云端硬盘。

Local Drive Sync 不是 Google 的产品，也不是 rclone 项目或其维护者运营的服务。本网站只说明这个客户端，本身不提供网盘、不同步文件、也不接受登录。

它做什么

用户在自己的电脑上运行 rclone 命令时，程序可以对该用户已授权的云端硬盘执行用户选中的操作：

  • 列出文件夹和文件
  • 上传、下载、复制、同步
  • 移动和重命名
  • 删除。rclone 默认把文件放进云端硬盘垃圾箱；只有用户自己关闭垃圾箱选项时才会直接删除
  • 挂载或校验

这些操作只在用户运行相应命令时发生。开发者不会远程触发它们。

它不做什么

  • 不访问 Gmail、通讯录、日历、相册或其他 Google 产品
  • 不把文件或令牌发送到开发者的服务器。开发者不运营这样的服务器
  • 不在本网站收集账号、文件或授权码
  • 不向公众提供注册或代管同步
  • 不把 Google 用户数据用于广告、出售、信用评估、借贷，或训练通用人工智能模型

为什么请求 Google 用户数据

rclone 要按用户的命令读写云端硬盘里已有的文件，需要用户在 Google 同意屏幕上授予这一个范围：

https://www.googleapis.com/auth/drive

Google 对这个范围的说明是：查看、修改、创建和删除你的全部 Google 云端硬盘文件。它不包含“应用数据文件夹”。没有这个范围，rclone 无法对用户云端硬盘里已有的文件执行上面列出的命令。本客户端只声明这一个范围。

更窄的范围做不到同一件事。例如 drive.file 只能看到本应用自己创建的文件，用户云端硬盘里原有的文件对 rclone 不可见，复制和同步会不完整。

授权发生在哪里

用户运行 rclone config 时，系统浏览器打开 Google 的同意屏幕。用户同意后，Google 把授权码送回用户电脑上 rclone 临时打开的本机地址。rclone 文档中的示例是 http://127.0.0.1:53682/。rclone 在这台电脑上用授权码换取令牌，并写入本机配置。

本网站不是 OAuth 重定向地址，不接收授权码，也不参与令牌交换。

数据留在哪里

访问令牌和刷新令牌保存在用户运行 rclone 的那台电脑上。文件内容只在这台电脑和 Google 之间传输。如果用户自己把云端硬盘中的文件复制到本机目录，或复制到用户自己配置的其他存储，文件会到达用户在命令里指定的位置。开发者不指定目的地，也不接收这些文件。

如何停止访问

用户可以随时打开 Google 账号的第三方访问权限，撤销 Local Drive Sync。撤销后，已经发出的刷新令牌失效。用户还应删除自己电脑上对应的 rclone 配置。开发者没有另一份令牌或文件可以删除。

谁在运营

由创建该 Google Cloud 项目的个人开发者运营。本页不公布姓名、邮箱或账号。需要联系开发者时，请使用 Google 授权同意屏幕上显示的用户支持邮箱。该地址与 Google Cloud 品牌页中填写的用户支持邮箱是同一个，授权时即可看到。

English

Local Drive Sync is the OAuth client a person uses so that rclone, on that person's own computer, can access a Google Drive that person is allowed to use.

What this application is

Local Drive Sync is the name of an OAuth client registered in a Google Cloud project. After the user enters that client in rclone config, the open-source program rclone can call the Google Drive API on the user's behalf.

The reason is the one given in the rclone documentation: the shared rclone client_id is being retired, and each user is told to create their own client. This client is used by the developer who created it, on computers that developer controls, for Google Drive accounts that developer is allowed to use.

Local Drive Sync is not a Google product, and it is not operated by the rclone project or its maintainers. This website only describes the client. It does not store files, sync anything, or offer a sign-in.

What it does

When the user runs an rclone command on their own computer, rclone can do the operation the user chose against the Drive they authorized:

  • List folders and files
  • Upload, download, copy, and sync
  • Move and rename
  • Delete. rclone sends files to the Drive trash unless the user turns trash off
  • Mount or check files

These operations run only when the user runs the command. The developer does not trigger them remotely.

What it does not do

  • It does not access Gmail, Contacts, Calendar, Photos, or any other Google product
  • It does not send files or tokens to a server run by the developer. There is no such server
  • This website does not collect accounts, files, or authorization codes
  • It is not a public hosted-sync product and it has no sign-up
  • It does not use Google user data for advertising, sale, credit, lending, or training generalized AI models

Why Google user data is requested

To read and write files that are already in the user's Drive, rclone needs the user to grant one scope on Google's consent screen:

https://www.googleapis.com/auth/drive

Google describes this scope as permission to see, edit, create, and delete all of the user's Google Drive files. It does not include the Application Data folder. Without it, rclone cannot run the commands above on files that are already in the Drive. This client declares only this scope.

A narrower scope does not provide the same function. drive.file, for example, can see only files this application created. Files already in the Drive stay invisible to rclone, so copy and sync would be incomplete.

Where authorization happens

During rclone config, the system browser opens Google's consent screen. After the user agrees, Google returns an authorization code to a temporary local address opened by rclone on that computer. The rclone documentation uses http://127.0.0.1:53682/ as the example. rclone exchanges the code for tokens on that computer and writes them into the local config.

This website is not the OAuth redirect URI. It does not receive the authorization code and it does not take part in the token exchange.

Where data stays

Access tokens and refresh tokens stay on the computer where the user runs rclone. File bytes move between that computer and Google. If the user copies Drive files into a local folder, or into another storage location the user configured, the files go to the destination in that command. The developer does not choose the destination and does not receive the files.

How to stop access

The user can revoke Local Drive Sync at any time on Google's third-party access page. Revocation invalidates the refresh token. The user should also delete the matching rclone config on their computer. The developer has no second copy of the token or the files to delete.

Who operates it

An individual developer operates the Google Cloud project that owns this client. This page does not publish a name, an email address, or an account identifier. To contact the developer, use the user support email shown on Google's OAuth consent screen. That address is the same support email entered on the Google Cloud branding page, and it is visible when the user authorizes the app.

How data is accessed, used, stored, shared, and deleted is in the privacy policy. Conditions of use are in the terms of service.
